# SMSC.ru — обзор

## Base URL

Базовый URL — Админка → Настройки, дефолт `https://smsc.ru`. Секреты и URL в `system_settings` (шифруются), не в env.

## Auth

В админке — только API-ключ. Адаптер по-прежнему примет логин+пароль, если они уже лежат в `system_settings`.

В логах не писать. Пустой секрет колбэка не блокирует старт: колбэк даёт 401, submit fail-closed, пока секрет не задан в Настройках.

## Формат

Все вызовы: HTTP POST, JSON (`fmt=3`). Не-JSON тело считаем ошибкой (не `pending`): иначе задание зависнет до таймаута.

## Методы

| Назначение | Путь | Флаг |
|---|---|---|
| Отправить HLR | `/sys/send.php` | `hlr=1` |
| Отправить Ping (Silent SMS) | `/sys/send.php` | `ping=1` |
| Оценка себестоимости (без отправки) | `/sys/send.php` | `cost=1` + `hlr=1` или `ping=1` |
| Статус / обогащение | `/sys/status.php` | `all=2` для HLR extras |
| Баланс кабинета SMSC | `/sys/balance.php` | — |

Клиентский `id` (31 бит): `SHA256("SEND:{hlr\|ping}:{item_uuid}")[0:4] & 0x7fffffff`, ноль заменяем на 1. Нужен, чтобы повтор после краша не создал вторую проверку.

## Ретраи транспорта

Повторяем только сеть / HTTP 408, 425, 429, 5xx и SMSC `error_code=9` (flood / rate limit). `error_code=2` (auth) — не ретраить. Остальные коды приложения — терминальный fail.

## Аккаунт

Платформа SMS использует **тот же** аккаунт SMSC, что старый проект HLR. Один callback URL на аккаунт. Параллельная работа двух приёмников запрещена — см. cutover в [`DEPLOY.md`](../../architecture/DEPLOY.md).
